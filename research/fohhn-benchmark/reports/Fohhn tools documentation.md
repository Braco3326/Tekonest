# Fohhn Designer freezes designs, never compares them

> **Read this first (tekinspi, 2026-10-24).** This report covers the **documentation only** (the deep-research pass). It was written before the live audit and the expert council were folded in. Three points have been superseded:
> - **Listener planes are captured per snapshot.** This was observed live (D-43 → D-44 in `../designer-snapshots.md`), which settles the documentation contradiction below.
> - **Snapshot list:** the list shows timestamps and has a search box, but no dot-numbering is visible (D-14, D-15, D-21).
> - **TekPractice fidelity ladder:** the ladder at the end of this report (closed-form STI at level b) is **not** the recommendation. The council blocked any computed STI value, and any absolute SPL next to legal limits, below an approved fidelity level (c). See `../scope-decision.md` and `../council/synthesis.md`.

Fohhn Designer's Help Centre, which requires a login, describes a snapshot as a versioned set of parameters arranged in a tree. Once a snapshot has been simulated it cannot be changed. If you edit while it is displayed, Designer clones it automatically. The snapshot holds room-acoustic parameters, loudspeakers and simulation settings, but **not the room geometry**. Comparing two snapshots means switching between them, and no side-by-side or difference view is documented (Documented; [HC-057](https://services.fohhn.com/hc/articles/z1mMgAg1), [HC-058](https://services.fohhn.com/hc/articles/J3w4qYbD)). Designer's four result modes are Direct SPL, Total SPL, STI and STIPA(IR). STI and STIPA rest on a statistical impulse response after Houtgast, following IEC 60268-16 Ed. 5.0 (2020). Early reflections use an image-source method, and the engine as a whole is geometric acoustics that ignores diffraction (Documented; [HC-054](https://services.fohhn.com/hc/articles/jYftIt24), [HC-055](https://services.fohhn.com/hc/articles/SFmj1bc0)). The other two tools are far less documented. The Fohhn Speaker Viewer (served at /fsd-viewer/) has one public sentence on the products page and one Help Centre release note. Nothing public defines "FSD" (Documented/Unknown; [Fohhn products](https://www.fohhn.com/en/products), [HC-066](https://services.fohhn.com/hc/articles/ILnL66vY)). The Optimizer is documented as a pink-noise measurement tool: it stores at most five measured spectra, which it also calls "snapshots", averages them, and proposes an EQ you paste into Fohhn Audio Soft 5.7 or later (Documented; [HC-077](https://services.fohhn.com/hc/articles/ycTEuJKc), [HC-074](https://services.fohhn.com/hc/articles/rzIAFJMs)). Peer tools split "snapshot" into two separate ideas, device presets and frozen results. None of them documents a spatial A−B difference map. For TekPractice, a defensible model ladder is (a) illustrative trends, (b) closed-form Hopkins-Stryker, Sabine/Eyring, ISO 9613-1 and RT/SNR-based STI, each unit-tested and labelled "average room estimate", and (c) a shoebox image-source model with STI derived from its impulse response, labelled as indicative only.

*Method and evidence conventions.* All sources were accessed on **2026-10-24**. Each claim carries one of three labels. **Documented** means stated in a named source: official Fohhn pages, the login-gated Fohhn Help Centre as captured by the researcher, vendor manuals, or the cited literature. **Inferred** means reasoned from documented facts. **Unknown** means searched for and not found. Fohhn material is paraphrased throughout, and quotation is limited to short UI labels. The 2020 novelty-group training handout is a distributor document that predates most release notes. Where it conflicts with the Help Centre, the Help Centre wins.

## Designer snapshots form an immutable tree, but geometry sits outside it

Fohhn presents snapshots as the organising idea of Designer: a design grows step by step, one snapshot at a time. The Help Centre defines a snapshot as the sum of the parameter changes to the room, the loudspeakers and the simulation settings. It explicitly leaves out the room geometry and the audience areas (Documented; [HC-057](https://services.fohhn.com/hc/articles/z1mMgAg1)). Fohhn's public product page describes the same idea in marketing terms: evolutionary concept development, with room and loudspeaker properties, simulation settings and results kept per snapshot, plus a modification history (Documented; [Fohhn Designer product page](https://www.fohhn.com/en/products/fohhn-designer)). **A simulated snapshot cannot be changed.** If you edit a parameter (Fohhn's example is moving a loudspeaker) while a simulated snapshot is shown, Designer clones it and applies the edit to the clone. Further edits collect in the clone until it is simulated. The clone becomes a child of the original, so the snapshots form a tree whose dot-separated numbers show depth (Documented; [HC-057](https://services.fohhn.com/hc/articles/z1mMgAg1)). Release notes back up this immutability. Version 1.10.0 (17.05.2021) fixed a bug that let users edit the reverberation time of a simulated snapshot. Version 0.19.2 (28.01.2020) fixed cases where rotating a listener plane or changing simulation settings failed to create a new snapshot (Documented; [HC-121](https://services.fohhn.com/hc/articles/he1MxiH7), [HC-130](https://services.fohhn.com/hc/articles/qf420TaR)).

The sources do not all agree on what a snapshot contains. The table below sets out the evidence.

| Item | Status | Source |
|---|---|---|

| Room acoustic parameters (RT per band) | Included (Documented) | [HC-057](https://services.fohhn.com/hc/articles/z1mMgAg1), [HC-121](https://services.fohhn.com/hc/articles/he1MxiH7) |
| Loudspeaker type, settings, position | Included (Documented) | [HC-057](https://services.fohhn.com/hc/articles/z1mMgAg1) |
| Simulation settings and results | Settings included (Documented); results implied, since the snapshot view is where you switch between results (Inferred) | [HC-058](https://services.fohhn.com/hc/articles/J3w4qYbD) |
| Listener planes | Contradictory: the article excludes them; the course slide and the 0.19.2 fix suggest they are tracked | [HC-057](https://services.fohhn.com/hc/articles/z1mMgAg1), [HC-090](https://services.fohhn.com/hc/course/qxHZnWDl/article/0iyCVUz0), [HC-130](https://services.fohhn.com/hc/articles/qf420TaR) |

| Broadband cutoffs, beam annotation display | Restored on switch (1.5.0) and snapshot-based (1.16.0) (Documented) | [HC-126](https://services.fohhn.com/hc/articles/dcgKwlyM), [HC-061](https://services.fohhn.com/hc/articles/SCzmy5rg) |

The tree tolerates one kind of drift. Geometry is shared across all snapshots, so replacing the room changes the context of every earlier result. **Designer's only response is a mismatch warning (1.7.0)**. It does not re-run old snapshots (Documented; [HC-124](https://services.fohhn.com/hc/articles/ZpRGFxjW)). Several operations are documented. You open the snapshot view through **Snapshots > Show**, by clicking the name in the status bar, or with CTRL+ALT+M. The view toggles between **List** and **Tree** (added in 0.17.0). Hovering an entry shows Rename and Delete, and the tree adds two centring commands. A **Delete Multiple** dialog offers Select All and Invert Selection, and the documentation warns that deletion cannot be undone. Deleting all snapshots keeps the current one by default (since 1.5.0) (Documented; [HC-058](https://services.fohhn.com/hc/articles/J3w4qYbD), [HC-037](https://services.fohhn.com/hc/articles/RnPzkYXF), [HC-132](https://services.fohhn.com/hc/articles/L7ZeGFNI), [HC-126](https://services.fohhn.com/hc/articles/dcgKwlyM)). Each snapshot takes its name from the simulation settings dialog, which auto-numbers it. An optional description shows in a hover flyout from 0.19.2, although the docs do not confirm that the flyout's "comment" is that description (Documented/Inferred; [HC-055](https://services.fohhn.com/hc/articles/SFmj1bc0), [HC-130](https://services.fohhn.com/hc/articles/qf420TaR)). There is **no explicit restore or revert command**. You "restore" by clicking a snapshot, and snapshot switches take part in undo and redo (Documented; [HC-057](https://services.fohhn.com/hc/articles/z1mMgAg1), [HC-134](https://services.fohhn.com/hc/articles/lDLVCu8n)). The docs do not cover timestamps, search, a confirmation on single deletes, or how the very first snapshot of a new project comes into being (Unknown; [HC-058](https://services.fohhn.com/hc/articles/J3w4qYbD)).

Comparison is the weakest part. The only documented way to compare is to switch quickly between snapshots. Result labels (point values placed on listener planes) stay in place when you switch, so the same seat can be read across variants. Version 1.7.0 added a comparison line to the spectrum tool, but nothing says it compares snapshots (Documented; [HC-057](https://services.fohhn.com/hc/articles/z1mMgAg1), [novelty handout, Snapshots slides](https://www.novelty-group.com/media/Formations/novelty-session-Fohhn-Designer-Basics-Online.pdf), [HC-124](https://services.fohhn.com/hc/articles/ZpRGFxjW)). Reports are tied to snapshots. Each report is built on one snapshot, and changing that snapshot or the report's SPL colour limits regenerates every picture and every data-driven resource (Documented; [HC-043](https://services.fohhn.com/hc/articles/gssfrO08), [HC-116](https://services.fohhn.com/hc/articles/1rQHYV5r)). A footer icon, added in 1.10.0, shows whether the selected snapshot complies with IEC 60268-16 (Documented; [HC-121](https://services.fohhn.com/hc/articles/he1MxiH7)). The full rule that decides the icon's state is Unknown.

## Projects are cloud objects with one room, two permission levels and no version history

Designer runs in the browser and calculates on Fohhn's servers. It is free with a Fohhn Services account, and it was launched around April 2019 (Documented; [Fohhn Designer page](https://www.fohhn.com/en/products/fohhn-designer), [TPi, 10 Apr 2019](https://tpimagazine.com/?p=33251), [Fohhn webinars](https://cloud.fohhn.com/en/webinars)). The project page lists your own projects, team projects and projects shared with you. You can search them by name, description and owner, and sort them by name or creation date. Each project's Details tab shows its owner, creation date and authors. Projects can be edited, deleted (after a confirmation), duplicated (reports included), shared, archived (which makes them read-only) and restored (Documented; [HC-011](https://services.fohhn.com/hc/articles/qEaS2pmJ), [HC-013](https://services.fohhn.com/hc/articles/GocgLRsU)). **Sharing has two levels, read-only and edit**, and invitees must be registered Designer users who accept the invitation. Teams with shared storage arrived in 1.13.0, on 29.09.2021 (Documented; [HC-014](https://services.fohhn.com/hc/articles/PfQlAU4z), [HC-064](https://services.fohhn.com/hc/articles/O2aIOD77)). Saving combines an autosave interval, an automatic save after every successful simulation (since 0.18.0), CTRL+S, and a marker for unsaved changes. Opening the same project twice produces a warning. **Snapshots are the only versioning mechanism.** No project version history is documented, and the History panel is a notification log that is discarded when the project closes (Documented; [HC-022](https://services.fohhn.com/hc/articles/bj4L5uap), [HC-131](https://services.fohhn.com/hc/articles/MMrUmyXB), [HC-021](https://services.fohhn.com/hc/articles/UeUlq4a6)).

The data model can be pieced together from the editor articles. A project holds **exactly one room**, a triangle mesh that must be watertight for the volume, the diffuse field and STI to come out right. The mesh comes from the box wizard or from an imported Collada (.dae) or EASE (.xfc) file. Imported material names are mapped to Designer's library, and since 1.8.0 the imported file itself is stored in the project (Documented; [HC-050](https://services.fohhn.com/hc/articles/Yo5OgvJx), [HC-051](https://services.fohhn.com/hc/articles/dttehbhz), [HC-052](https://services.fohhn.com/hc/articles/qEmniMGq), [HC-123](https://services.fohhn.com/hc/articles/BLzYYqdu)). Walls carry materials, which start as "Global". Reverberation time is entered per band, or calculated from the materials with a choice of Eyring or Sabine, and an RT that does not match the materials raises a plausibility error that does not block simulation (Documented; [HC-118](https://services.fohhn.com/hc/articles/07zLdJlb), [HC-051](https://services.fohhn.com/hc/articles/dttehbhz)). Listener planes are flat polygons, which may have holes. Each is triangulated, and **the triangle centres are the evaluation points**. Its resolution is set per plane, with a warning below 1 m and another above 20,000 points. The default ear height is 1.2 m (Documented; [HC-027](https://services.fohhn.com/hc/articles/pLkhdMPG), [HC-024](https://services.fohhn.com/hc/articles/BAgdNsyC), [HC-130](https://services.fohhn.com/hc/articles/qf420TaR), [HC-126](https://services.fohhn.com/hc/articles/dcgKwlyM)). Loudspeakers come only from the Fohhn catalogue, as Single Source, Beam Steering or Bass types. Their parameters are gain (attenuation only, −80 to 0 dB), mute, delay, position and rotation, high-pass and low-pass filters, a band EQ limited to cuts, and, where the model supports them, beam parameters (angle, width, optimize) and bass-stack settings (count, spacing, polarity) (Documented; [HC-032](https://services.fohhn.com/hc/articles/nO383bLw), [HC-030](https://services.fohhn.com/hc/articles/2maslJnV)). Beams can be exported to Fohhn Audio Soft as an FFC file, or the whole design as a complete Audio Soft project. The report configurator generates PDFs whose links last one day, plus a ZIP of images (Documented; [HC-016](https://services.fohhn.com/hc/articles/pDKLmhtf), [HC-046](https://services.fohhn.com/hc/articles/HFQDcMDM), [HC-113](https://services.fohhn.com/hc/articles/49wHbBbj)).

## Four render modes rest on geometric acoustics plus a statistical reverberant field

The snapshot view offers four render types: **Direct SPL, Total SPL, STI and STIPA(IR)**. The two SPL modes can be shown per band or as broadband with adjustable cutoffs and A or C weighting (Documented; [HC-058](https://services.fohhn.com/hc/articles/J3w4qYbD)). The settings dialog chooses octave or 1/3-octave bands. It also offers a background-noise spectrum that only affects STI, early reflections by the image-source method (with order and time lag; the default lag became 35 ms in 1.21.2), and air damping driven by temperature, humidity and pressure. "Consider room collision" checks whether each point can see the source and is turned off automatically when early reflections are on. A **complex summation limit** sums sources coherently below a chosen frequency and energetically above it, and "Calculate Multi-Source as Single-Source" trades near-field accuracy for speed (Documented; [HC-055](https://services.fohhn.com/hc/articles/SFmj1bc0), [HC-060](https://services.fohhn.com/hc/articles/M8qCDT4r), [HC-121](https://services.fohhn.com/hc/articles/he1MxiH7)). Fohhn calls the method geometric acoustics: sound travels as straight rays, classical reflection laws apply, and **diffraction is ignored** (Documented; [HC-054](https://services.fohhn.com/hc/articles/jYftIt24)). This corrects the 2020 handout, which listed no reflection modelling. Early reflections were added in 1.10.0 (Documented; [HC-121](https://services.fohhn.com/hc/articles/he1MxiH7)).

The Help Centre never defines Direct SPL versus Total SPL in words. It only says that Total SPL and STI need a solid room with the correct volume, because the volume drives the diffuse field, while Direct SPL tolerates leaky models (Documented; [HC-095](https://services.fohhn.com/hc/course/qxHZnWDl/article/ESYMUYQ1), [HC-050](https://services.fohhn.com/hc/articles/Yo5OgvJx)). The distributor handout's theory slides describe Total SPL as direct sound plus a diffuse part built from total loudspeaker energy, room volume and reverberation time. They cite Sabine and recommend Eyring when mean absorption exceeds 0.25 (Documented, secondary; [novelty handout, "TOTAL SPL" and "Formule de Sabine" slides](https://www.novelty-group.com/media/Formations/novelty-session-Fohhn-Designer-Basics-Online.pdf)). That shape matches a Hopkins-Stryker statistical model. **Fohhn never names the algorithm**, so this identification is Inferred. STI uses a statistical room impulse response after Houtgast et al., which IEC 60268-16 calls statistical prediction, an indirect method. It follows Edition 5.0 (2020-09) and ignores direct-sound delays unless the user enables "Include travel times in STI calculation", which voids compliance. **STIPA(IR)** is the indirect, impulse-response-derived STIPA, added in 1.16.0 (19.04.2022). In the same release STI Female was removed, following the 2020 edition of the standard (Documented; [HC-054](https://services.fohhn.com/hc/articles/jYftIt24), [HC-055](https://services.fohhn.com/hc/articles/SFmj1bc0), [HC-061](https://services.fohhn.com/hc/articles/SCzmy5rg)). Fohhn repeats the standard's advice to use a measured RT. The handout adds that RT can only be calculated for a closed room (Documented; [HC-054](https://services.fohhn.com/hc/articles/jYftIt24), [novelty handout, Snapshots-2](https://www.novelty-group.com/media/Formations/novelty-session-Fohhn-Designer-Basics-Online.pdf)). One 1.6.0 note says reverberation is derived automatically "from the loudspeakers" when no RT is entered. Its meaning is Unknown ([HC-125](https://services.fohhn.com/hc/articles/x755Mjdh)). The colour-scale gradient is fixed. Only the lower and upper limits can be edited, and their defaults are set in Options. STI uses its own scale, and the documentation gives no threshold or pass/fail colouring (Documented; [HC-019](https://services.fohhn.com/hc/articles/P8fRcnsg)).

## The Speaker Viewer and Optimizer are thin on documentation and share only a word with Designer

**Fohhn Speaker Viewer.** The products page gives it one line: it shows a speaker's dispersion pattern per frequency and opens its measurement charts. It links to services.fohhn.com/fsd-viewer/, which shows only a login page (Documented; [Fohhn products](https://www.fohhn.com/en/products), [FSD Viewer entry page](https://services.fohhn.com/fsd-viewer/)). The Software series page does not list it ([Fohhn software series](https://fohhn.com/en/series/software)). The Help Centre has no user documentation for it, only one release note, 1.4.0 (25.01.2022). That note fixed wrong frequencies in the **polar chart** and the **balloon view**, the only views named anywhere (Documented; [HC-003](https://services.fohhn.com/hc/categories/LHaQgzE5), [HC-066](https://services.fohhn.com/hc/articles/ILnL66vY)). The meaning of "FSD", the file schema, resolution, normalisation, smoothing and comparison features are all **Unknown**. "Fohhn Speaker Data" is a plausible expansion, but it is only an inference. The fuller view list some people assume (Cabinet, Frequency Response, Impedance, Isobars, DI) matches the CLF viewer's industry-standard set, but no Fohhn source confirms it (Inferred; [CLF viewer](http://www.clfgroup.org/viewer.htm), [CLF release notes](http://www.clfgroup.org/clfdocuments.htm)). Fohhn publishes speaker data for EASE, CLF, ulysses and Designer. The AT-05 page, for example, describes a compact passive 2-way point source with 90°×90° dispersion and 88 dB sensitivity, not a column or beam-steered model (Documented; [Fohhn AT-05](https://fohhn.com/en/products/at-05)). No open licence covers CLF, GLL or Fohhn data (Documented absence; [CLF FAQ](http://www.clfgroup.org/faq.htm)).

**Fohhn Optimizer.** The product page describes a login-gated web tool. It measures the room's effect on a Fohhn system playing pink noise, using either a smartphone joined by QR code or a microphone on the PC, and proposes EQ for the device's DSP from Fohhn's "Famsa" algorithm, which is not otherwise described. The page frames the proposal as a starting point (Documented; [Optimizer product page](https://www.fohhn.com/en/catalog/fohhn-optimizer), [German page](https://www.fohhn.com/de/katalog/fohhn-optimizer)). The Help Centre adds the procedure. You load a standard preset with no EQ in Audio Soft, run pink noise, and measure several listener positions. **"Take Snapshot" stores one measured spectrum, up to five in total.** The chart shows them normalised to 0 dB at 1 kHz with the live trace in black, and "Calculate EQ" averages them. The settings control band averaging, sampling time, rise and fall averaging, the working range, maximum Q, the maximum number of filters, and a Strict or Moderate mode that scales the gains. The resulting parametric table can be copied into Fohhn Audio Soft 5.7 or later, and an empty table means no optimisation was possible or needed (Documented; [HC-072](https://services.fohhn.com/hc/articles/aCWZkCFm), [HC-075](https://services.fohhn.com/hc/articles/3fZ0Xela), [HC-076](https://services.fohhn.com/hc/articles/WbTeAFIR), [HC-077](https://services.fohhn.com/hc/articles/ycTEuJKc), [HC-074](https://services.fohhn.com/hc/articles/rzIAFJMs)). An Optimizer snapshot is a measured spectrum in a list capped at five, while a Designer snapshot is a versioned simulation state. **The two share only a name.** The launch date rests on a single third-party video title from InfoComm 2022 (Documented, secondary; [YouTube](https://www.youtube.com/watch?v=AeBPjx30xEk)). Default settings, manual filter editing and deleting individual snapshots are Unknown. The research literature sets a ceiling on what any such tool can achieve. Single-point inverse EQ degrades when the microphone moves a few tenths of a wavelength, and multi-point least-squares EQ improves uniformity over an area without being exact anywhere (Documented; [Radlović et al. 2000](https://researchportalplus.anu.edu.au/en/publications/equalization-in-an-acoustic-reverberant-environment-robustness-re/), [Elliott & Nelson 1989](https://eprints.soton.ac.uk/468661)).

## Peer tools split "snapshot" into presets and frozen results, and compare on locked scales

Across the industry the word "snapshot" covers two different objects. Device snapshots hold processor settings. MAPP 3D's Snapshot Library lets you create, update and recall per-processor settings by overwriting them (Documented; [MAPP 3D user guide](https://docs.meyersound.com/products/en/user-guide---mapp-3d.html)). ArrayCalc's Snapshots relate to amplifier groups and R1 conflicts, so they are most likely operational presets (Inferred from [ArrayCalc release notes](https://www.dbaudio.com/assets/products/downloads/software/arraycalc/dbaudio-release-notes-arraycalc-v10.26.4.pdf)). Result snapshots freeze a simulation. Examples are ArrayCalc's 3D plot memories, which can be reloaded as project state and carry a description of the simulated signal; Adamson Blueprint AV's captures; Martin Audio DISPLAY 3's optimisation snapshots for different audience or weather scenarios; and EASE 5's Simulation Configurations, which AFMG says serve as both calculation presets and saved results (Documented; [ArrayCalc notes](https://www.dbaudio.com/assets/products/downloads/software/arraycalc/dbaudio-release-notes-arraycalc-v10.26.4.pdf), [Blueprint AV](https://legacy.adamson.ai/product/system-control/blueprint-av), [Martin Audio, 21 Sep 2026](https://martin-audio.com/news/press-release/martin-audio-releases-next-generation-prediction-and-optimisation-software-display), [EASE upgrade history](https://www.afmg.eu/en/ease-upgrade-history)). Designer's tree, which is immutable once simulated, belongs to the second kind and is the most formal branching model among the peers.

| Tool | Snapshot-like object | Frozen or live | Comparison mechanism |
|---|---|---|---|
| Fohhn Designer | Snapshot tree (params + results, no geometry) | Frozen once simulated; geometry mismatch warning | Switch between snapshots; persistent result labels ([HC-057](https://services.fohhn.com/hc/articles/z1mMgAg1)) |
| d&b ArrayCalc | 3D plot memory; device Snapshot | Memories frozen; edits interrupt live calc | One colour scale for live and memory views ([release notes](https://www.dbaudio.com/assets/products/downloads/software/arraycalc/dbaudio-release-notes-arraycalc-v10.26.4.pdf)) |
| Meyer MAPP 3D | Processor snapshot; stored traces | Prediction on demand | Overlay of up to 5 traces with dB offset ([user guide](https://docs.meyersound.com/products/en/user-guide---mapp-3d.html)) |
| AFMG EASE 5 | Simulation Configuration | Real-time (Acousteer); configs double as saved results | User-fixed colour scale, Fixed Interval, FR overlay ([upgrade history](https://www.afmg.eu/en/ease-upgrade-history)) |
| AFMG EASE Focus 3 | Named source/area groups | Live, progressive resolution | RELATIVE tolerance view ([user guide](https://engineering.purdue.edu/ece40020/DesPrj/EASE_Focus_3_User_Guide.pdf)) |
| L-Acoustics Soundvision | Multiple array iterations | Real-time | Toggle iterations ([FOH, 2019](https://fohonline.com/articles/power-tools/the-art-of-noise-exploring-l-acoustics-soundvision/)) |

Three patterns stand out. First, **no vendor documents a spatial A−B difference map**. Comparison relies on locked shared colour scales (EASE 5 added one specifically to make maps comparable, and ArrayCalc applies one scale to live and memory views), on trace overlays, or on switching views (Documented absence across the sources above). Designer's per-map limits and switching-only comparison sit at the simpler end of that range (Inferred). Second, the tools keep display settings apart from calculation settings. MAPP 3D re-renders a resolution change without recalculating, and EASE 5 removed item activation from undo because it counts as a calculation setting (Documented; [MAPP 3D](https://docs.meyersound.com/products/en/user-guide---mapp-3d.html), [EASE history v5.74](https://www.afmg.eu/en/ease-upgrade-history)). Third, no tool documents automatic staleness flags on stored results. Designer's room-mismatch warning and ArrayCalc's traffic-light Project report come closest (Documented; [HC-124](https://services.fohhn.com/hc/articles/ZpRGFxjW), [ArrayCalc notes](https://www.dbaudio.com/assets/products/downloads/software/arraycalc/dbaudio-release-notes-arraycalc-v10.26.4.pdf)). Outside audio, Onshape makes versions immutable and requires a branch before editing, and Figma checkpoints the current state before any restore. Both are models for a teaching game's try-a-variant loop (Documented; [Onshape help](https://cad.onshape.com/help/Content/Document/versions_and_history.htm), [Figma help](https://help.figma.com/hc/en-us/articles/360038006754-View-a-file-s-version-history)).

## TekPractice can be honest at three fidelity levels if each carries its validity label

**Level (a), illustrative**, shows trends and promises no numbers. Examples are a line source falling about 3 dB per doubling in its near field against 6 dB in the far field, a comb-filter demo from coherent summation of two sources, a rectangular-room mode map, and an STI gauge driven by RT and SNR sliders. Line arrays belong here because published transition-distance formulas disagree by a factor of about 6 to 8, and the 3 dB trend ripples by about ±2 dB (Documented; [Q-SYS white paper](https://www.qsys.com/resource-files/whitepapers/q_wp_cin_linearraysincinema.pdf), [L-Acoustics WST paper](https://www.l-acoustics.com/wp-content/uploads/2026/06/Wavefront_Sculpture_Technology_convention.pdf)). Synthetic directivity (a baffled piston or a cardioid) avoids the licensing problems of measured CLF or GLL data (Inferred, textbook models not verified this session).

**Level (b), simplified and validated**, uses closed-form models with unit tests and stated limits. Direct SPL is sensitivity + 10·log P − 20·log r + DI − air absorption. The air-absorption term follows ISO 9613-1, which is valid for pure tones from 50 Hz to 10 kHz and is implemented in open code (Documented; [acoustic-toolbox docs](https://acoustic-toolbox.readthedocs.io/en/latest/atmosphere/), [ISO 9613-1 preview](https://webstore.ansi.org/preview-pages/ISO/preview_ISO+9613-1-1993.pdf)). The sensitivity-plus-power term is textbook and was not verified from a fetched source. Total SPL follows Hopkins-Stryker, Lp = LN + 10·log(Q/4πr² + 4/R), alongside Sabine and Eyring reverberation time. The Engineering ToolBox worked example recomputes to **84.5 dB**, not the 84.8 dB printed on the page, which makes it a useful regression test (Documented, recomputed; [Engineering ToolBox](https://www.engineeringtoolbox.com/sound-propagation-indoor-d_72.html), [Wikipedia: Reverberation](https://en.wikipedia.org/wiki/Reverberation)). These models give a spatially averaged reverberant level, not the level at a particular seat. They are unreliable below the Schroeder frequency, 2000·√(T/V), which is about 189 Hz for a 45 m³ room with a 0.4 s RT (Documented; [akutek](https://akutek.info/articles_files/stochastics.htm), [samesound](https://acoustic.samesound.ru/en/learn/schroeder-frequency)). STI from RT and SNR uses the Houtgast-Steeneken diffuse-field modulation transfer function across 7 bands and 14 modulation frequencies. The exact formula and the later STI steps are marked must-verify against IEC 60268-16 before shipping (Unknown for verbatim text; [Wikipedia: STI](https://en.wikipedia.org/wiki/Speech_transmission_index), [IOA, Barnett](https://www.ioa.org.uk/system/files/publications/PW%20BARNETT%20BS%207443%20SOUND%20SYSTEMS%20FOR%20EMERGENCY%20PURPOSES%20AND%20SPEECH%20INTELLIGIBILITY%20-%20AN%20OVERVIEW.pdf)). The qualification bands are bad, poor, fair, good and excellent, with boundaries at 0.30, 0.45, 0.60 and 0.75. The standard itself sets no voice-alarm pass criterion. The 0.50 average and 0.45 minimum targets come from CEN/TS 54-32 and NFPA 72, so the game should never print "compliant" (Documented; [Wikipedia: STI](https://en.wikipedia.org/wiki/Speech_transmission_index), [AFNOR listing](https://www.boutique.afnor.org/en-gb/standard/iec-60268162020/sound-system-equipment-part-16-objective-rating-of-speech-intelligibility-b/xs137999/250690), [LDA Audiotech](https://lda-audiotech.com/en/2020/12/16/intelligibility-in-voice-evacuation-systems/)). Broadband results should be energy sums of octave bands after A or C weighting computed from the IEC 61672 analytic formula (Documented; [Wikipedia: A-weighting](https://en.wikipedia.org/wiki/A-weighting)). This level maps directly onto Designer's statistical Total SPL and STI (Inferred).

**Level (c), advanced**, adds position-dependent early reflections and an impulse response, from which STI(IR) and C50/C80 can be derived. A shoebox image-source model in TypeScript is feasible in the browser and can be cross-tested against pyroomacoustics (MIT licence) and studied alongside the MIT-licensed browser simulator "band". GPL engines should not be copied into the game (Documented; [pyroomacoustics](https://pyroomacoustics.readthedocs.io/), [band](https://github.com/gregzanch/band), [RoomAcoustiC++](https://roomacousticpp.readthedocs.io/)). The honest label is "indicative". The third round robin found that every geometric-acoustics algorithm showed model errors outside the mid frequencies, and that auralisations were always audibly different from measured ones (Documented; [Brinkmann et al. 2019, CC BY 4.0](https://depositonce.tu-berlin.de/items/9b719f33-8772-4739-920a-c4ade8a48572/full)). Earlier PTB round robins found that professional tools disagreed so widely in one auditorium that reliable prediction seemed impossible, so measured benchmarks such as BRAS (CC BY-SA 4.0) and PTB should be used for teaching rather than as pass/fail tests (Documented; [PTB Round Robin](https://www.ptb.de/cms/ptb/fachabteilungen/abt1/fb-16/ag-163/round-robin-in-room-acoustics.html), [BRAS](https://depositonce.tu-berlin.de/items/38410727-febb-4769-8002-9c710ba393c4/full)).

## Conclusion

Studying Designer changes what "snapshot" should mean for TekPractice. Fohhn's documents show a design-history tree, not a comparison tool. It is strict about immutability, loose about the shared room geometry (a warning, not invalidation), and silent on side-by-side comparison. Peers fill the comparison gap with locked shared colour scales and overlays rather than difference maps. A teaching game can therefore make an original contribution with three features. It can stamp every snapshot with a hash of its inputs and the version of its calculation model, so drift shows as a badge rather than a silent mismatch. It can force a shared scale in A/B mode. And it can offer a true difference map, which no documented vendor provides (Inferred). The game must also keep Designer-style design snapshots apart from Optimizer-style measurement snapshots, because Fohhn's own reuse of the word shows how easily learners could confuse them.

On physics, the game's honesty depends on labels more than on fidelity. Designer itself pairs geometric direct sound with a statistical reverberant field and statistical STI. Level (b) closed-form models therefore reproduce the same family of approximations a professional tool uses, provided the game shows the Schroeder limit, the "average room estimate" caveat and the non-compliance of travel-time STI. The highest-value open items are verification tasks. The verbatim STI formula needs checking against IEC 60268-16. The contradiction over whether listener planes belong in snapshots, and the behaviour of the first snapshot in a new project, need a live audit. The Speaker Viewer's actual view set and the meaning of "FSD" need the same live check before TekPractice states anything about them.
