### Q1 Architecture

**Decision: new shell, strangler pattern.**

- `src/main.ts` routes:
  - default → `src/creation/boot.ts`;
  - `?legacy=1` (or any `?level=`) → today's router, unchanged.
- `FEATURES.levels = false` lives in a new `src/features.ts`.

New modules:

| Module | Role | Reuses |
|---|---|---|
| `src/creation/boot.ts` | composition root; the only place that wires things | — |
| `src/creation/store.ts` | `CreationStore`: `DesignState` + selection + dirty flag + `dispatch(intent)`. It applies intents to `ConnectionGraph`, runs `RuleEvaluator`, notifies subscribers. Headless, no DOM, no Babylon | `engine/*`, `trials/trial.ts` `DesignState` |
| `src/creation/history.ts` | undo/redo stack (C5) | `trials/fingerprint.ts` (tests) |
| `src/creation/sceneHost.ts` | **one** Babylon `Engine` for the page; `load(place, design)` builds a `Scene`; `dispose()` tears it down (C3) | `RoomBuilder`, `DeviceSpawner`, `CableRenderer`, `CameraRig`, `ViewDirector`, `designerOrbitInput`, `orbitFeel`, `cameraTween` |

- **Extraction from `game.ts`.** Only what both shells need is extracted, and only when the second user appears: `applyDesign`/`captureDesign` → `src/scene/designApplier.ts`, and port projection → `src/scene/project.ts`. `game.ts` then calls the extracted code. Legacy e2e must stay green after every extraction.
- **`dispose()` path.**
  - `SceneHost.dispose()` calls, in order: `focusPatch.dispose()`, `cube.dispose()`, `orbitInput.dispose()`, `explore.dispose()`, `cables.dispose()`, each `DeviceInstance.dispose()`, `scene.dispose()`.
  - The `Engine` survives.

### Q2 Power and playback (CA-03)

**Mains.** New generic catalog device `multiprise-secteur` ("Multiprise (cordons IEC)"), generic per the CLAUDE.md trademark rule:

- 4 ports `out-1…out-4`, `dir: out`, connector `iec-c13`, signal `mains-power`, flag `isMainsSource`;
- `realWorld.notes` say honestly: "Représente une multiprise branchée au secteur avec ses cordons IEC".

R1 (`iec-c13` ↔ `iec-c14`), R2 (mains-power ↔ mains-power) and R3 (out → in) already accept it. **No engine change.** This is not a violation of ADR-0001: ADR-0001 rejected modelling a *switch* as a cable. A mains cord *is* a cable.

**Power switch.** A `power` toggle control (default `true`, label "Interrupteur secteur") on every device with a `mains-power` input that is active electronics (QL1, K12.2, DBR12, Genelec 8030C, playout-pc, …). It is ADR-0001 state, mutated by `SET_CONTROL`.

**A device is powered** iff:

- its `power-in` is connected to a port flagged `isMainsSource`, **and**
- its `power` control is `true` (or the device has no `power` control).

**Playback.**

- A QL1 control `playback-usb` (toggle, default `false`, label "Lecture console (USB)") is added. A real QL1 plays from a USB stick into the mix, so this is a control, not a port.
- A new optional catalog field `devices[].routing`:

  ```jsonc
  "routing": [
    { "from": "in-mic-1", "to": ["out-main-l", "out-main-r", "out-mix-1"] },
    { "from": "in-mic-2", "to": ["out-main-l", "out-main-r", "out-mix-1"] },
    { "source": "playback-usb", "label": "Lecture console", "to": ["out-main-l", "out-main-r"], "enabledBy": "playback-usb" }
  ]
  ```

- Pass-through devices get routes too: K12 `in-line-a → thru-out-a`, DBR12 `in-line → link-out`.
- `playout-pc` gets `{ "source": "player", "to": ["out-analog-consumer"] }` with no `enabledBy`, so a laptop or player counts as a source.
- `validate-catalog` checks that the route ports exist and the directions are right.
- `ConnectionGraph` never reads `routing`. Only `src/flow/signalPath.ts` does, so the engine stays audio-agnostic.

**Gate predicate**: `signalPath(snapshot, registry)` returns

```text
{ sources[], speakers[{ instanceId, receivesSignal, powered, path[], reasons[] }],
  micOk[], playbackReady, blockers[] }
```

- `playbackReady` is true iff:
  - an enabled source exists (a route with `source`, with `enabledBy` on, or none required);
  - the device that hosts the source is **powered**;
  - a path exists from the source over routes and connections to the `in-*` port of a device flagged `transducer` (new catalog field `acoustic`, see C12);
  - that speaker is **powered**;
  - no `TeachingEvent` with `severity: 'error'` has a subject port on that path.
- Mute and fader **do not** affect the gate (C9). They make the speaker silent and its meter flat.
- `micOk` is true for each mic `out` connected to an `isMicInput` port of a **powered** console whose input has a route. Phantom matters only if the mic `requiresPhantom` (R4 logic reused). For the SM58 (dynamic) it is true without +48 V.

**Exactly true for QL1 + SM58 + 2 × K12.2:**

| Thing | Requirement |
|---|---|
| Multiprise | `out-1→QL1.power-in`, `out-2→K12-L.power-in`, `out-3→K12-R.power-in`; `power` on for all three (default) |
| Signal | `QL1.out-main-l → K12-L.in-line-a`, `QL1.out-main-r → K12-R.in-line-a` |
| Playback | `QL1.playback-usb = true` (set from the Écoute panel: "Source : Lecture console") |
| Mic | `SM58.out-xlr → QL1.in-mic-1` gives "Micro OK" (independent of the music gate) |

The starter template « Concert simple (référence) » (L3) contains all of this except the two signal cables and the playback choice, so the student still patches.

### Q4 View cube, 26 zones, render on demand

**Camera and render target:**

- `cubeCam` is an `ArcRotateCamera` at a fixed radius that mirrors the main camera's `alpha`/`beta` on `onViewMatrixChangedObservable`.
- `cubeCam.layerMask = 0x10000000`; the cube meshes use the same mask; the main camera's mask excludes it.
- `scene.activeCameras = [main, cubeCam]`, `scene.cameraToUseForPointers = main`.
- Viewport top-left: 120 px at 1366, 130 px at ≥ 1600 (C-a). The cube is drawn in its own rendering group so its depth is cleared.
- **One engine, one WebGL context.** The DOM cube in `src/ui/viewCube.ts` is retired in Mode Création; legacy keeps it.

**Zones.**

- One box mesh (with the labels baked once into a `DynamicTexture`: Face, Arrière, Gauche, Droite, Dessus, Dessous).
- A pure classifier maps the local hit point p ∈ [−1, 1]³ to s_i = sign(p_i) if |p_i| > 0.5, else 0. The non-zero triplets give exactly 26 zones: 6 faces, 12 edges, 8 corners.
- Each band is 25 % of a face edge: about 18 px at 120 px. From a ¾ pose a corner patch spans three faces, about 30 px.
- Hover: an Ambre overlay quad on the hovered zone, plus the zone name under the cube (never colour alone).

**Angles** (extend `src/camera/viewCube.ts`):

| Zone | alpha | beta |
|---|---|---|

**Interaction:**

- A click inside the cube viewport is picked with `cubeCam`, and the camera flies (450 ms, reduced motion = cut) around the current pivot.
- A drag on the cube orbits the main camera.
- ↻ ↺ ⌂ are DOM buttons beside the cube.
- A compass ring with 4 cardinal ticks is drawn as a flat mesh on the same layer.
- All 26 zones are also buttons in **Vue → Vues** and a `V` + arrows picker (C-d).

**Render on demand (whole app).**

- `RenderScheduler` keeps `engine.runRenderLoop(tick)`. `tick` returns at once unless one of these holds:
  1. `dirty` was set by `invalidate()`;
  2. a tween is active;
  3. the main camera's inertial offsets (`inertialAlphaOffset`, `inertialBetaOffset`, `inertialRadiusOffset`, `inertialPanningX/Y`) are non-zero;
  4. an "animating" lease is held (wavefronts, meters, a held cable following the pointer).
- `invalidate()` is wired to:
  - pointer, wheel and key events on the canvas;
  - `camera.onViewMatrixChangedObservable`;
  - `scene.onNewMeshAddedObservable` / `onMeshRemovedObservable`;
  - asset `modelReady`;
  - resize;
  - every store change.
- Counted in `window.__audioSim.renders()`.
- **Low-end:** if `render/detect.ts` reports a software renderer, call `engine.setHardwareScalingLevel(1.5)` and use a coarser dot grid (proposal).

### Q5 Acoustics module

**Pure core** `src/acoustics/`: `directivity.ts`, `field.ts`, `sum.ts`, `stats.ts`, `listenerMix.ts`, `scale.ts`. No Babylon, no DOM.

**Directivity:**

- θh = atan2(x', z') and θv = atan2(y', √(x'² + z'²)) in the speaker's local frame (yaw, then tilt).
- u² = (θh / (H/2))² + (θv / (V/2))².
- **D = max(−6·u², −30) dB.** This is a Gaussian in dB with an elliptical combination: exactly −6 dB at each half coverage angle, monotonic, and smooth on axis.
- Floor −30 dB for |θ| ≥ 90° and beyond (rear). The ADR states that it is a teaching shape, not measured balloon data.

**Field:** L_i = L_ref + D − 20·log10(max(r, 0.5 m) / 1 m). Energetic sum L = 10·log10(Σ 10^(L_i/10)) over the speakers that `receivesSignal && powered && !muted`. Fader and console gain in dB are added to L_ref.

**Display:** relative to the maximum (0 dB), clamped at −24, in 3 dB bins.

**Estimated SPL (≈ dB SPL estimé):** only if every contributing speaker has a sourced `sensitivity_db` and `max_spl_db`: L_ref = min(max_spl_db, sensitivity_db + 10·log10(nominal drive)). Otherwise `null` and the option is disabled with its reason.

**Worker boundary:**

- `field.worker.ts` gets `{ jobId, speakers: [{ pos, yawDeg, tiltDeg, covH, covV, lrefDb }], plane: { y, rects[] }, step }`.
- It returns `{ jobId, levels: Float32Array (transferable), stats }`.
- The main thread debounces 150 ms on store changes and drops stale `jobId`s.
- Grid step adapts so points ≤ 20,000: 0.5 m, then 1 m, then 2 m (arena 75 × 53 at 0.5 m = 15.9 k; festival → 1 m; stadium → 2 m).
- The plane is the audience zones (`kind: audience`) or the floor, at 1.2 m (seated) or 1.7 m (standing).

**Catalog provenance** (zod-required). New optional `devices[].acoustic`:

```jsonc
"acoustic": {
  "transducer": true,
  "coverage_h_deg": { "value": 90, "source": { "kind": "datasheet|kb|nominal", "ref": "<URL or knowledge-base/equipment/... path>", "retrieved": "YYYY-MM-DD" } },
  "coverage_v_deg": { … }, "sensitivity_db": { … }, "max_spl_db": { … }
}
```

- `kind: "nominal"` is allowed only with the values 90 / 60 and shows « valeur nominale ».
- Values are copied from `knowledge-base/equipment/*.json` with their cited source. **No value is typed from memory.**

**Golden tests (vitest):**

1. On axis at 2r vs r: −6.02 dB ±0.01.
2. θh = H/2, θv = 0: −6.00 ±0.01. Same for θv = V/2.
3. Two equal sources at the same point: +3.01 ±0.01.
4. An unpowered, unsignalled or muted speaker contributes 0.
5. Normalisation: max = 0, everything ≥ −24, bins of 3 dB.
6. Stats on a fixed array: min, max, mean, σ, count.
7. SPL estimate is `null` when any speaker lacks a source.
8. `listenerMix`: r = 343 m gives a 1.000 s delay; gain ∝ 1/r (2r gives −6.02 dB); pan = dot(dir, listenerRight) is −1 for a speaker on the rendered left.
9. Rear floor: −30 dB at 180°.

### Q7 Risks and cut order

- **Performance on software GL** (14 fps today, idle = orbit).

- **Bundle.**

  - Lazy chunks: acoustics + worker, Web Audio, inventory drawer, place picker thumbnails.
  - Songs fetched on demand, ≤ 4 MB each.
  - The Draco runtime fetch is removed (CA-24).
- **Scope.** 38 tasks over 5 phases. The biggest unknowns: multi-camera depth clear (T2.2 proves it first), and move-with-cables (T3.2), because `CableRenderer` must update endpoints on `SET_POSE`.
