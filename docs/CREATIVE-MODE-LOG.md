The compass ring stays at the cube's base even though it sets the size limit (raising it would gain ≈ 4 px but read as a belt; tekdesigner's call). - **L15 (Task 19).** Walking in Mode Création uses **no pointer lock**: left-drag looks, right-drag moves, keyboard alone works (arrows, or ZQSD/WASD by key position), so Échap always reaches the shell. Places without a room layout (« Salle vide neutre », the 3D venue sets) get a single « Centre » point instead of a « Régie » that wouldn't exist. Keys are fixed: 1 = Régie (or Centre), 2 = Premier rang, 3 = Fond de salle; a room without that point says so. The active point resets to Régie on every place change and is not saved across reloads. **For Oscar:** the plan's acceptance line "Régie exists for every place" now reads "every room has a Régie; a place without a layout has Centre".

Les câbles ne sont pas sélectionnables au clavier (suite possible).
- **L18 (Task 30).** Onglet « Bêta » : **le fichier de propositions existe**, rien n’est inventé. Cherché : `proposal` sous `tekpractice-sim/content/` et `docs/`, `tools/propose-content.ts` (étape finale de `npm run sync:kb`), `knowledge-base/`. Trouvé : `tekpractice-sim/content/proposals/catalog-proposals.json` (généré le 2026-10-22 depuis `knowledge-base/equipment/*.json`, appareils « forte valeur simulateur » absents du catalogue) : **134 appareils** valides au schéma `Device` du catalogue, aucun doublon, aucun déjà au catalogue, 23 écartés par le générateur (listés dans `skipped`). L’onglet lit exactement ce fichier ; `content/catalog.json` n’est pas modifié. **Conception :** pour être posé, un appareil doit être dans le registre que partagent le store, le spawner et les panneaux ; une proposition y est donc enregistrée pour la session (`src/creation/betaDevices.ts`), seulement quand on la choisit ou qu’un projet enregistré en a besoin, avec ses seuls ports déclarés (jamais de réglage inventé : les `controls` éventuels sont retirés). `registry.catalog.devices` reste intact (le catalogue, la validation et le tiroir ne voient que le matériel vérifié) ; `isUnverified(registry, id)` est l’unique définition de « non vérifié ». Le fichier (200 kB de source, chunk minifié de 149 kB / 23 kB gzip) est un **chunk lazy** (`proposalsSource`), chargé à la première ouverture du tiroir, ou au démarrage seulement si l’autosave contient un appareil inconnu du catalogue. **Rechargement :** la fiche est encore proposée → l’appareil revient ; la fiche a disparu (la synchro ne la propose plus) ou le fichier est illisible → l’appareil n’est pas rechargé et une note le dit (« Appareils non rechargés », avec les identifiants), l’autosave d’origine est mise de côté comme pour tout élément perdu. **Échec du chargement ≠ fiche disparue (fix round 1) :** si la requête échoue ou ne répond pas en 5 s (hors ligne, réseau bloqué), le projet n’est **pas** appliqué, rien n’est mis de côté, l’autosave est suspendue (`betaHold` : l’instantané est nul, donc rien n’écrase le projet enregistré), le sélecteur de lieu s’ouvre avec la note « Fiches Bêta indisponibles (réseau). Rechargez la page pour retrouver votre projet. » ; recharger sans échec rouvre le projet intact. Si l’apprenant commence autre chose avant (choisit un lieu, ouvre un projet), le projet retenu est d’abord mis de côté (récupérable par « Exporter les données mises de côté… » : fichier JSON, pas encore de réimport, voir L12) puis l’autosave reprend. « Ouvrir… » dans le même cas n’ouvre rien et ne change rien. Au premier chargement du tiroir, un échec laisse l’onglet masqué et le tiroir s’ouvre. **Honnêteté :** pastille « non vérifié » + info-bulle dans le tiroir, pastille dans l’arbre Projet et mention sous le titre de Propriétés ; R1–R3 lisent le connecteur et le signal déclarés, R4–R8 les drapeaux déclarés, « Signal OK » reste conditionné à `playbackReady` (Task 34). **Consigne explicite pour la Task 34 :** le chemin du signal qui alimente `playbackReady` doit **s’arrêter à tout appareil `isUnverified(registry, id)`** (`src/creation/betaDevices.ts`) : un appareil Bêta ne rend jamais une chaîne « jouable », et son test doit l’affirmer dès que le module existe. En attendant, « Aucune erreur détectée » dit « N appareil(s) non vérifié(s) » à côté du signal quand le montage en contient (R4–R8 tournent sur des drapeaux « à vérifier à la main »). **Pour Oscar :** les données livrées n’ont **pas été relues par le fondateur**, seulement marquées « non vérifié » (le README et l’en-tête `status` du fichier le disent maintenant) ; les drapeaux des propositions (`providesPhantom`, horloge, `isMonitorOut`, Dante) et les catégories restent « à vérifier à la main » (README des propositions) ; un identifiant de port comme `in-balanced-input-per-channel-1` vient tel quel de la base de connaissances.
