# Storyboard du tutoriel « Premiers pas » (images fixes)

Brouillon pour le fondateur. Images fixes uniquement : aucune vidéo, aucune animation (autorisation du 2026-11-12 : images fixes et storyboards ; toute vidéo seulement après que Vous avez vu ce storyboard).

Une ligne par étape capturée : treize images, prises dans le vrai jeu en 1366 x 768. Les images sont dans `tekpractice-sim/docs/tutorial/captures/`.

## Ce qui n’est PAS montré

- **Aucune vidéo, aucune animation, aucun son.** « Signal de test » est une étape ; l’image ne se fait pas entendre.
- **Packages 2, 3 et 4.** Ils jouent les mêmes dix étapes que le package 1, avec un autre habillage ; ils ne sont pas capturés. Les cinq adresses, sur le serveur local de `npm run onboarding:local` (port 4392) : `/?design=1`, `/?design=2`, `/?design=3`, `/?design=4`, `/?design=5`. Seuls le package 1 (dix étapes) et le package 5 (trois étapes) sont dans ce storyboard.
- **L’écran de démarrage** (« Je découvre », « Faire le tutoriel ») et **la carte de fin** après l’étape 10 (ou 3) ne sont pas capturés ; chaque série commence à l’étape 1, une fois « Faire le tutoriel » choisi.
- **Les autres tailles d’écran** (tablette, portrait) : 1366 x 768 seulement.
- **Ce que vit une vraie personne** : ces images montrent un parcours fait par un script qui suit le cadre d’Oscar à la souris ; rien ici ne mesure un temps ni une hésitation.

## La vue 3D est visible : à regarder avant de montrer

Les images montrent la vraie scène 3D du jeu (si elle était masquée, six cadres sur treize entoureraient une zone vide). Les modèles portent des images dérivées de photos produit : **ne montrez ces images à personne avant de les avoir regardées** (spec 12). Pour les refaire sans la scène 3D : `CAPTURE_HIDE_3D=1` (voir plus bas) ; les étapes dont le cadre est sur la vue 3D échouent alors, avec ce message.

## Les images ne sont pas dans git

`docs/tutorial/captures/` est ignoré par git (`docs/tutorial/.gitignore`). Pour les refaire (PowerShell, depuis `tekpractice-sim`, le port 4392 doit être libre : arrêtez `npm run onboarding:local` s’il tourne) :

```powershell
$env:E2E_PORT = '4392'
npm run build
$env:CAPTURE = '1'
npx playwright test tests/e2e/tutorial-captures.spec.ts --workers=1
Remove-Item Env:CAPTURE
```

Sans `CAPTURE=1`, le fichier de test est ignoré (« skipped »). Une exécution efface et réécrit les treize images et `manifest.json` (ce que la page a dit à chaque étape, et ce que la route a fait ensuite). Le dernier test vérifie que ce storyboard cite chaque image et chaque ligne d’Oscar exactement comme la page l’a montrée : si la copie du produit change, il échoue et ce fichier est à mettre à jour.

## Comment lire les annotations

Deux numéros par image, chacun un chiffre ambre dans un disque nuit avec une flèche ambre. Le numéro est celui de la case « Étape k » de la carte de progression. Le premier numéro désigne ce que le cadre d’Oscar entoure (l’action à faire), le second la bulle d’Oscar (sa phrase). Les annotations sont dessinées par-dessus la page dans une couche à part ; elles ne couvrent ni texte ni bouton, et aucun disque ni flèche n’est posé sur du Papier (vérifié sur les pixels).

L’icône d’Oscar est lue sur la page : sur chaque image il est dans la pose « point » (il montre).
